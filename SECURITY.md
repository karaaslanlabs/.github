# Security Policy

Security reports are welcome and should be handled privately.

## Reporting a vulnerability

Please do **not** open a public GitHub issue for a suspected security vulnerability.

Send a concise report to:

**contact@karaaslanlabs.com**

Include, when possible:

- the affected repository, component, or URL;
- a clear description of the issue;
- reproducible steps or a minimal proof of concept;
- the security impact you believe is possible;
- relevant versions, commits, or environment details;
- any suggested mitigation, if known.

Do not include unnecessary personal data, credentials, production secrets, or data belonging to other users.

## Scope and handling

We will review reports based on reproducibility, impact, and the affected project's current support status. Not every bug is a security vulnerability, and public repositories may have different deployment or support states.

Please allow time for investigation before public disclosure. If a report is confirmed, we will coordinate remediation and disclosure as appropriate for the affected project.
